**決定: env ファイルの更新は「prefix 単位の全置換」にする（追記ではない）**

同一 prefix の既存 `export` 行を落としてから現在値を書き直す。prefix に一致しない行は保持する。

理由: セッション中に設定が変わったとき、追記方式だと同じ変数の古い値が残り、shell が
source した際にどちらが勝つかがファイル内の行順に依存する。行順依存は再現困難な不整合を生む。
「最後に書いた値が唯一の値」という不変条件を保つには全置換が要る。

却下した代替案:

- **追記のみ（既存行を残す）**: 実装は最も単純だが、上記の行順依存が残る。NFR-003
  （再実行時に旧値を残さず最新値へ更新される）を満たせない。
- **env ファイルを毎回空にしてから書く**: 旧値問題は解けるが、他の prefix（他プラグインが
  書いた行）を巻き込んで消してしまう。共有ファイルへの副作用が大きすぎる。

**決定: 書き込みは tmp ファイル + replace で原子的に行う**

理由: env ファイルは shell が source する対象であり、書きかけの状態を読まれると
未定義の変数や構文エラーになる。`replace` は同一ファイルシステム上で原子的なので、
source する側が半端な状態を観測しない。

却下した代替案: **ロックファイルで排他する** — source する側（shell）はロックを取らないため、
書き手同士は排他できても読み手との競合は防げない。原子的置換で読み手側の問題が消えるなら
ロックは不要。
